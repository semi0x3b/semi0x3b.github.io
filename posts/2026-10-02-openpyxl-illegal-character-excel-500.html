답변 하나에 섞인 NUL 문자로 openpyxl 엑셀 다운로드가 통째로 500이 됐어요

답변 하나에 섞인 NUL 문자로 openpyxl 엑셀 다운로드가 통째로 500이 됐어요

2026년 10월 02일10 min read

(지원서 답변 하나의 원문) cannot be used in worksheets.

관리자 화면(어드민)에서 지원자 엑셀을 내려받으면 500이 났어요. 지원서가 많이 쌓인 모집이었어요. 위 줄이 이때 난 예외 메시지예요. 괄호 자리에는 지원서 답변 하나가 통째로 들어 있었어요. 뒤쪽 문장은 openpyxl이 IllegalCharacterError를 던질 때 붙여요.

그 답변에 NUL 문자가 섞여 있었어요. NUL은 코드 값이 0인 제어문자이고 화면에 보이지 않아요. openpyxl은 이런 제어문자를 셀에 쓰지 못하고 예외를 던져요. 행 하나에서 난 예외 때문에 파일이 끝까지 만들어지지 않았고 요청은 500으로 끝났어요. 셀에 쓰기 직전에 이런 제어문자만 지우는 함수를 만들었어요. 어드민에서 엑셀을 만드는 기능 8개가 모두 이 함수를 거치게 했어요.

로그에 없는 요청 추적하기

처음에는 서버 로그부터 봤어요. 지원자 엑셀 요청은 성공도 실패도 보이지 않았어요. 다른 화면의 엑셀 요청은 200으로 남아 있었어요. 그래서 요청이 로그에 보이지 않는 이유를 하나씩 확인했어요.

  • 브라우저의 사전 요청이 막혔나: 브라우저는 다른 도메인의 API에 별도 헤더를 실어 보내기 전에 OPTIONS 요청으로 허락을 먼저 구해요. 이게 사전 요청이에요. API 앞에서 요청을 받아 넘기는 게이트웨이가 그 OPTIONS 요청에 200을 줬어요. 엑셀 암호를 싣는 헤더도 응답의 허용 헤더에 들어 있었어요.
  • 요청이 앱까지 못 오나: 인증 없이 같은 주소를 직접 불렀더니 401이 돌아왔어요. 앱 로그에도 그 요청이 찍혔어요.
  • 파일을 만드는 도중에 프로세스가 죽었나: 컨테이너 안에서 메모리 부족으로 강제 종료된 프로세스 수(oom_kill)는 0이었어요. 워커 프로세스가 다시 뜬 기록도 없었어요.
  • 화면이 보내는 항목 이름이 서버와 다른가: 화면이 보내는 항목 키는 서버 허용 목록에 모두 있었어요.

4개 모두 아니었어요. 다운로드를 다시 시도하자 실패가 일어났고, 그때 난 예외의 메시지에 cannot be used in worksheets.가 있었어요. 로그를 본 건 이 시도보다 앞이었어요. 조사를 시작하게 한 처음의 실패가 왜 로그에 보이지 않았는지는 확인하지 못했어요.

셀에 쓸 수 없는 문자 확인하기

xlsx 파일은 XML 문서를 압축해 묶은 형식이에요. XML 1.0은 0x20보다 작은 문자 가운데 탭, 줄바꿈, 캐리지 리턴 3개만 허용해요. openpyxl은 문자열을 셀에 넣기 전에 금지된 문자가 있는지 검사하고, 하나라도 있으면 IllegalCharacterError를 던져요. 금지 범위는 라이브러리 안에 정규식으로 들어 있어요.

\000 같은 값은 8진수 표기예요. 풀어 쓰면 코드 값이 0x00~0x1F인 제어문자 가운데 3개를 뺀 나머지가 금지예요. 빠지는 3개는 탭(0x09), 줄바꿈(0x0A), 캐리지 리턴(0x0D)이에요. NUL(0x00)은 금지 범위에 들어가요.

재현은 짧아요.

Traceback (most recent call last):
  (중간 생략)
openpyxl.utils.exceptions.IllegalCharacterError: ab cannot be used in worksheets.

터미널은 NUL을 그리지 않아서 a와 b가 붙어 보여요. 운영에서 난 예외도 같은 모양이었어요.

  • 행 하나면 파일 전체가 실패해요. 이 다운로드는 행을 차례로 쓴 다음 한 번에 저장해요. 중간 행에서 예외가 나면 저장까지 가지 못하고 요청은 500으로 끝나요. 지원서가 아무리 많아도 답변 하나에만 섞여 있으면 결과는 같아요.
  • 예외 메시지에 셀 값이 통째로 들어가요. 메시지는 {셀 값} cannot be used in worksheets. 꼴이에요. 어떤 답변에서 났는지가 메시지에 그대로 보였어요. 예외를 그대로 로그에 남기면 사용자 입력도 같이 남아요.

그 답변은 저장돼 있었고, 예외는 엑셀 셀에 쓸 때 났어요. NUL이 어떻게 답변에 섞였는지는 확인하지 못했어요.

쓰기 직전에 제어문자만 지우기

행을 셀에 쓰기 직전에 거치는 함수를 하나 만들었어요.

  • 지우는 범위는 openpyxl의 검사 범위와 같아요. 검사에 쓰는 정규식을 그대로 가져다 썼어요.
  • 줄바꿈과 탭은 지우지 않아요. 여러 줄로 쓴 답변은 줄이 나뉜 채로 셀에 들어가요.
  • 문자열만 손대요. 숫자, 날짜, 빈 값은 그대로 넘겨요.

그다음 코드에서 sheet.append( 같은 행 쓰기 호출을 검색해 어드민에 있는 자리를 모두 찾았어요. 찾은 자리를 이 함수로 감쌌어요.

실패가 확인된 건 지원자 엑셀 하나였지만, 어드민에서 엑셀을 만드는 기능 8개를 전부 고쳤어요. 사람이 입력한 문자열을 거르지 않고 셀에 쓰는 구조가 모두 같았어요. 한 곳만 고치면 같은 문제가 다른 엑셀에 남아요.

이번 수정에 넣지 않은 것도 있어요.

  • 입력 검증: 제출 단계에서 제어문자를 막는 검증은 넣지 않았어요. 입력을 막더라도 이미 저장된 답변은 그대로라서, 엑셀을 쓰는 쪽에서 지우는 처리는 어느 쪽이든 필요해요.
  • 규칙 검사: 새 엑셀 다운로드도 이 함수로 감싼다는 규칙은 문서로만 남겼어요. 이 규칙을 검사하는 테스트는 아직 없어요.

테스트로 확인하기

  • 회귀 테스트: NUL과 수직 탭이 섞인 문자열, 줄바꿈과 탭이 든 문자열, 숫자, 빈 값을 한 행으로 써요. 제어문자만 빠지고 나머지는 그대로 셀에 들어갔는지 확인해요.
  • 운영 반영: 수정은 운영에 반영했어요. 반영한 뒤 같은 모집의 엑셀을 다시 내려받아 확인한 기록은 남기지 못했어요.

사용자가 입력한 글을 openpyxl로 엑셀에 쓰고 있다면, 행을 쓰는 자리를 함수 하나로 모으고 ILLEGAL_CHARACTERS_RE로 걸러 두면 돼요.
