부트캠프 홈이 강의 정보를 불러오지 못한 날 (10규칙판)

부트캠프 홈이 강의 정보를 불러오지 못한 날 (10규칙판)

2026년 7월 28일11 min read

🎯 7월 28일 아침, 부트캠프 홈이 강의 정보를 불러오지 못했습니다. 새로 켜진 서버가 아직 손님을 받을 준비가 안 됐는데 요청이 들어갔기 때문입니다. 서버가 “준비됐다”고 알리는 절차를 22개 서비스에 넣어 해결했습니다.

무슨 일이 있었나

아침 8시 28분에 부트캠프 홈이 바라보는 API 주소를 새 주소로 바꿔 배포했더니 강의 목록이 뜨지 않았고, 16분 뒤에 되돌렸습니다.

가게로 비유하면 이렇습니다. 새 지점을 열면서 간판은 걸었는데 직원이 아직 출근하지 않았습니다. 손님은 문을 열고 들어갔지만 맞아줄 사람이 없어서 그냥 나왔습니다. 간판이 걸렸다는 사실과 장사할 준비가 됐다는 사실은 다른데, 우리 시스템은 그 둘을 구분하지 못했습니다.

왜 그랬나

강의 정보를 담당하는 서버가 새로 켜질 때, 아직 접속을 받을 수 없는 상태인데도 요청이 그리로 전달됐습니다.

부트캠프 홈의 API 주소를 바꾸자 강의 서버로 요청이 몰렸습니다. 요청이 늘면 서버 대수를 자동으로 늘리는 장치가 작동해서 새 서버를 띄웠습니다. 그런데 이 서버에는 “나 이제 요청 받을 수 있어요”라고 알릴 방법이 없었습니다. 그래서 켜지자마자 요청 배분 목록에 올라갔고, 실제로는 아직 준비 중이던 몇 초 동안 들어온 요청이 전부 실패했습니다.

실패한 요청은 55건이었고, 전부 부트캠프 홈에서 온 것이었습니다. 강의 목록, 상단 메뉴, 신청 내역처럼 홈 화면을 채우는 데이터가 여기 포함됐습니다.

💡 처음에는 문의 기능이 새 환경에 없어서라고 봤는데, 확인해보니 그건 쓰지 않는 기능이었습니다. 접속 경로나 인증 문제도 아니었습니다. 실제 원인은 요청이 서버까지 도달하지 못하고 거절된 것이었고, 이건 서버 쪽 기록을 보고서야 확인됐습니다.

무엇을 바꿨나

세 가지를 고쳤고, 운영과 개발 환경에 모두 반영했습니다.

바꾼 것어떻게 바꿨는지
준비 상태를 확인하는 절차서비스 20개에 넣었습니다. 이제 서버가 실제로 접속을 받을 수 있을 때만 요청 배분 목록에 올라갑니다. 이미 갖추고 있던 두 서비스의 방식을 그대로 따랐습니다.
강의 서버의 최소 대수운영 환경에서 한 대에서 두 대로 늘렸습니다. 한 대뿐일 때는 서버를 늘리는 동안 그 한 대가 모든 요청을 감당해야 합니다.
자동 확장과 배포 도구의 충돌배포 설정에서 대수 지정을 뺐습니다. 그동안은 자동 확장이 늘려둔 대수를 배포할 때 다시 줄일 수 있는 상태였습니다.

배포할 때 확인해야 할 한 가지

배포 도구로 반영하기 전에, 지금 돌고 있는 이미지와 코드에 적힌 이미지가 같은지 확인합니다.

배포는 코드에 적힌 대로 서버를 다시 맞추는 작업입니다. 설계도대로 건물을 정리하는 것과 비슷해서, 설계도에 없는 증축분은 헐립니다. 코드를 거치지 않고 바로 올린 이미지가 있다면 그게 조용히 옛 버전으로 돌아갑니다.

이번 하루에만 이런 경우를 일곱 건 만났습니다. 운영 환경 두 건은 미리 확인해서 막았고, 개발 환경 다섯 건은 제가 이 확인을 건너뛰는 바람에 실제로 되돌아갔습니다. 그중 둘은 당일 올린 빌드였습니다. 복구는 마쳤습니다.

확인은 이 명령 하나면 됩니다.

차이가 나오면 코드 쪽을 지금 돌고 있는 버전에 맞춰 고친 뒤에 배포합니다. 반대로 하면 운영 중이던 빌드가 사라집니다.

배포 직후 반영이 안 될 때

코드를 올린 직후에 배포를 돌리면, 배포 도구가 아직 이전 코드를 보고 있어서 반영이 안 될 수 있습니다. 이번에도 한 번 겪었습니다. 성공했다고 나오는데 버전이 그대로였습니다.

이럴 때는 배포 도구가 어느 시점 코드를 썼는지 확인하고, 다르면 새로 읽어오게 한 뒤 커밋 번호를 직접 지정해서 다시 돌리면 됩니다.

아직 남은 일

  • 부트캠프 홈의 API 주소를 새 주소로 다시 바꾸는 작업. 서버 쪽 준비는 끝났고, 이번에는 코드를 거쳐서 진행하면 이력이 남습니다.
  • 자동 확장이 정한 서버 대수를 배포 도구가 아예 넘보지 않도록 하는 설정. 지금은 코드에서 대수 지정을 빼는 것까지 해뒀습니다.
  • 데이터베이스 접속 정보를 다른 설정값들과 같은 곳으로 옮기는 작업. 지금은 이것만 별도 파일에 남아 있는데, 그 파일이 없는 상태로 배포하면 빈 값으로 덮일 수 있습니다.
  • 개발 환경의 개인 작업용 앱 네 개와 정기 실행 작업 하나. 되감길 수 있어서 담당자 확인 후에 진행할 예정입니다.
